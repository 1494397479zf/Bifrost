1. 第1章 绪论（约 3000 字）
  1.1 研究背景
    - 互联网业务数据与访问量持续增长，传统单机数据库在可扩展性与高可用方面的瓶颈
    - 分布式关系型数据库集群逐渐成为支撑核心业务的主流形态
    - 异构数据库迁移、集群在线扩缩容、数据一致性校验在实际运维中的共性难题
  1.2 研究意义
    - 工程意义：降低大规模数据库运维复杂度，减少扩容与迁移过程中的业务中断风险
    - 应用价值：支持异构环境下的数据迁移与同步，为企业平滑演进数据库架构提供工具支撑
    - 学术意义：探索面向特定分布式数据库架构的逻辑层迁移与在线重分片方法
  1.3 国内外研究与系统现状概述
    - 典型分布式数据库系统的架构特点（对应第2章中的架构A/B/C）
    - 典型数据迁移与同步系统的能力与局限（云上迁移服务、基于 binlog 的同步框架等）
    - 典型在线扩缩容与重分片方案的思路及不足
  1.4 本文研究内容与创新点
    - 研究内容概述：面向路由层 + 控制节点 + 存储节点架构，设计并实现一套支持全量迁移与基于 binlog 增量同步的迁移与扩缩容系统
    - 创新点归纳（初步规划）：
      * 面向特定分布式集群架构的 Slot 级在线重分片机制
      * 基于 binlog 的逻辑层迁移与扩缩容方案，而非修改数据库内核
      * 基于“伪从库”思想的非侵入式数据一致性校验模块
      * 覆盖任务配置、拓扑展示、监控告警的 Web 可视化运维界面
  1.5 论文结构安排
    - 概述各章节主要内容与逻辑关系（第2章介绍相关技术与现状，第3章进行系统需求分析，第4章给出系统总体设计，第5章展开关键模块实现，第6章给出测试与评估，第7章总结与展望）

2. 第2章 相关技术与研究现状（约 2500～3000 字）
  2.1 分布式关系型数据库典型架构对比
    2.1.1 架构A：计算与存储分离的分布式数据库系统
      - 特点：前端无状态 SQL 层 + 全局元数据 / 调度组件 + 多副本存储节点
      - 优点：扩展性好，资源水平扩展方便
      - 局限：扩缩容通常依赖内核内置机制，外部迁移 / 扩缩容工具介入空间有限
    2.1.2 架构B：单进程多租户式的分布式数据库系统
      - 特点：节点通过内部协议组成一体化集群，通过分区 / 副本实现高可用
      - 优点：整体资源利用率高，对应用透明
      - 局限：迁移与重分片逻辑封装在内核中，对通用迁移 / 扩缩容平台支持度有限
    2.1.3 架构C：路由层 + 控制节点 + 存储节点的分布式数据库集群
      - 路由层节点（Spider）负责解析 SQL 并根据分片规则将请求转发到存储节点
      - 控制节点（dbctl）维护全局元数据和分片路由表
      - 存储节点（DataNode）以 shared-nothing 方式分别存储不同分片数据
      - 特点：对应用屏蔽分片细节，但迁移与扩缩容时必须同时考虑分片与路由更新
  2.2 数据迁移与同步系统典型架构
    2.2.1 云上数据迁移服务通用架构
      - 支持全量迁移（基于快照 / 导出导入）与增量同步（基于 binlog / 变更流的 CDC 组件）
      - 提供任务管理、链路监控、告警等管控能力
      - 局限：通常是“黑盒服务”，对特定分布式数据库架构的分片规则和路由机制支持有限
    2.2.2 基于 binlog 的开源同步框架
      - 通过复制协议接入源库，拉取 binlog 并解析为内部事件模型
      - 支持写入下游数据库或消息队列，实现近实时数据同步
      - 局限：多面向单实例或简单主从拓扑，对“路由层 + 控制节点 + 多存储节点”架构缺乏专门适配
  2.3 在线扩缩容与重分片方案
    2.3.1 传统停机扩容方案
      - 停机 + 全量导出导入 + 修改配置 + 重启，扩容过程对业务影响较大
    2.3.2 内核内置重分片方案
      - 由数据库内核在后台完成数据重分布，对应用相对透明
      - 局限：强依赖具体产品实现，难以统一管理多种数据库或跨集群扩缩容
    2.3.3 逻辑层迁移与重分片方案
      - 在数据库外部构建迁移 / 同步引擎，基于 binlog 捕获变更，结合分片规则进行逻辑迁移
      - 优点：可插拔、跨系统复用性好
      - 难点：需要深入理解目标集群的分片与路由机制
  2.4 小结与本课题架构定位
    - 总结以上几类数据库架构、迁移 / 同步系统及扩缩容方案的特点与不足
    - 明确本文聚焦于 2.1.3 所描述的“路由层 + 控制节点 + 存储节点”架构
    - 本文拟采用 2.3.3 所述逻辑层迁移与重分片方案，构建面向该架构的迁移与扩缩容系统
